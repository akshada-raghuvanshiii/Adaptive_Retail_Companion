Before you start

Once per boot.

Wi-Fi off, loopback multicast on
Terminal K
nmcli radio wifi off && sudo ip link set lo multicast on && ros2 daemon stop

Nothing in the run needs internet. Wi-Fi changes have cut Gazebo off from ROS mid-run before; multicast on lo lets the nodes find each other.

Quick way: one command, then three terminals

Bring-up opens and checks the simulation, SLAM, mapping and navigation windows for you (the same T1–B6 as the manual way). It loads your own teb_controller.yaml.

Bring up the stack
Terminal K≈ 15 min
cd ~/arc_test_kit && source env.sh && ./bringup.sh all

Ends with navigation stack is up. auto_map drives the store for about 8 min first: don't touch the robot. B6 is set to LEAD for you.

RViz
Terminal R
source ~/arc_test_kit/env.sh && rviz2 -d ~/arc_compact_store_kit/run/arc_nav.rviz --ros-args -p use_sim_time:=true

Map, scan, robot and the yellow /planned_path.

Store labels (B8)
Terminal L
source ~/arc_test_kit/env.sh && python3 ~/arc_compact_store_kit/ros_tools/item_markers.py

Aisle and item labels appear in RViz on /arc/store_markers.

Shopping Manager (B7), always last
Terminal S
source ~/arc_test_kit/env.sh && ros2 run arc_planner shopping_manager

Enter the shopping list in this window when it asks. The cart drives to each item in nearest-next order.

Change the BT mode while it runs
B6_person_state window

Click into the B6_person_state window and type 3 (LEAD) or 1 (FOLLOW). With 2 or 4 the cart does not move.

Check the pose against Gazebo (any time)
Terminal K
source ~/arc_test_kit/env.sh && python3 ~/arc_compact_store_kit/ros_tools/check_frames.py --model arc --samples 1

PASS means the map pose is within 0.15 m and 5° of the truth.

Shut everything down
Terminal K
~/arc_test_kit/bringup.sh stop && nmcli radio wifi on

Closes all nodes, including RViz, labels and the Shopping Manager, then turns Wi-Fi back on.

Manual way: every terminal yourself

Use this if gnome-terminal windows don't open, or to show each node during a demo. Each command already starts with source ~/arc_test_kit/env.sh. Wait for each check before the next row.

Clean start
Terminal K
~/arc_test_kit/bringup.sh stop

Kills anything left from earlier runs.

T1 Gazebo, compact store
T1
source ~/arc_test_kit/env.sh && ros2 launch arc_store_sim store.launch.py world:=arc_store.sdf

The compact store opens. world:= is required: the launch default is the old store.

T2 Robot description
T2
source ~/arc_test_kit/env.sh && export TURTLEBOT3_MODEL=burger && ros2 launch turtlebot3_gazebo robot_state_publisher.launch.py use_sim_time:=true

Robot initialized.

T3 Spawn the robot, then the bridge
T3
source ~/arc_test_kit/env.sh && ros2 run ros_gz_sim create -name arc -file $(ros2 pkg prefix turtlebot3_gazebo)/share/turtlebot3_gazebo/models/turtlebot3_burger/model.sdf -x 0.0 -y 0.0 -z 0.01 -Y 0.0 && ros2 run ros_gz_bridge parameter_bridge --ros-args -p config_file:=$HOME/slam_ws/src/arc_store_sim/config/arc_store_burger_bridge.yaml -p use_sim_time:=true

Robot at x 0, y 0, yaw 0 (required, so map = world). Check in Terminal K: timeout 4 ros2 topic hz /scan ≈ 5 Hz.

T5a ICP lidar odometry
T5a
source ~/arc_test_kit/env.sh && ros2 run rtabmap_odom icp_odometry --Icp/PointToPlane true --Icp/VoxelSize 0.05 --Icp/MaxCorrespondenceDistance 0.5 --Icp/Iterations 10 --Icp/Epsilon 0.001 --Icp/OutlierRatio 0.7 --Icp/CorrespondenceRatio 0.2 --Odom/ScanKeyFrameThr 0.4 --OdomF2M/ScanSubtractRadius 0.05 --OdomF2M/ScanMaxSize 15000 --Reg/Force3DoF true --ros-args -p use_sim_time:=true -p frame_id:=base_footprint -p odom_frame_id:=icp_odom -p guess_frame_id:=odom -p publish_tf:=true -r scan:=/scan -r odom:=/odom_icp

Check: timeout 4 ros2 topic hz /odom_icp ≈ 5 Hz.

T5b RTAB-Map, new map
T5b
source ~/arc_test_kit/env.sh && ros2 run rtabmap_slam rtabmap -d --Reg/Strategy 1 --Reg/Force3DoF true --Grid/Sensor 0 --Grid/RangeMin 0.2 --RGBD/NeighborLinkRefining true --Optimizer/GravitySigma 0 --Icp/PointToPlane true --Icp/VoxelSize 0.05 --Icp/MaxCorrespondenceDistance 0.5 --ros-args -r __ns:=/rtabmap -p use_sim_time:=true -p frame_id:=base_footprint -p subscribe_depth:=false -p subscribe_rgb:=false -p subscribe_scan:=true -p approx_sync:=true -r scan:=/scan -r odom:=/odom_icp

Check: timeout 5 ros2 run tf2_ros tf2_echo map base_footprint near 0, 0.

Map the store
Terminal K
source ~/arc_test_kit/env.sh && python3 ~/arc_compact_store_kit/ros_tools/auto_map.py

Expect 11 reached, 0 skipped and a small map error. No BT, teleop or Shopping Manager while it drives.

Lock the map
Terminal K
source ~/arc_test_kit/env.sh && ros2 service call /rtabmap/set_mode_localization std_srvs/srv/Empty

Then check_frames.py (step n7) should PASS.

B1 Controller (your TEB-like)
B1
source ~/arc_test_kit/env.sh && ros2 run nav2_controller controller_server --ros-args --params-file $HOME/slam_ws/src/arc_planner/config/teb_controller.yaml -r cmd_vel:=/cmd_vel_nav

Waits for B2 to activate it.

B2 Lifecycle manager
B2
source ~/arc_test_kit/env.sh && ros2 run nav2_lifecycle_manager lifecycle_manager --ros-args -r __node:=lifecycle_manager_controller -p use_sim_time:=true -p autostart:=true -p node_names:="['controller_server']"

Managed nodes are active.

B3 Dijkstra planner
B3
source ~/arc_test_kit/env.sh && ros2 run arc_planner dijkstra_planner --ros-args -p use_sim_time:=true

Gets the map from RTAB-Map.

B4 Path to TEB
B4
source ~/arc_test_kit/env.sh && ros2 run arc_planner planned_path_to_teb --ros-args -p use_sim_time:=true

B5 BT stack + motion gate
B5
source ~/arc_test_kit/env.sh && ros2 launch arc_behavior_tree arc_bt_stack.launch.py

B6 Person state
B6
source ~/arc_test_kit/env.sh && ros2 run arc_behavior_tree person_state_input

Type 3 (LEAD) or 1 (FOLLOW). With 2 or 4 nothing moves. Keep this window to change modes.

RViz and labels (B8)
Terminal R
source ~/arc_test_kit/env.sh && (python3 ~/arc_compact_store_kit/ros_tools/item_markers.py &) && rviz2 -d ~/arc_compact_store_kit/run/arc_nav.rviz --ros-args -p use_sim_time:=true

Optional, but this is what you show.

B7 Shopping Manager, last
B7
source ~/arc_test_kit/env.sh && ros2 run arc_planner shopping_manager

Enter the list when it asks.

Don't mix runs. Never run the Shopping Manager together with the test runner (./run.sh a2 etc.), and never teleop while the BT stack is up: the motion gate owns /cmd_vel.
